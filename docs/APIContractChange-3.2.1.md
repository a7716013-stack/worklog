# API changes — 3.2.1

Six new GET resources, protected by existing ApiResearchRead session policy and ReadPolicy: `/api/v1/data/providers`, `/api/v1/etl/jobs`, `/api/v1/etl/jobs/{id}`, `/api/v1/etl/jobs/{id}/quality`, `/api/v1/etl/batches/{id}/lineage`, `/api/v1/etl/health`. Provider/job lists use page 1..1000000 and pageSize 1..200 (default 50). Jobs whitelist provider, terminal status and sort=started-desc|id. Stable tie-break is job ID. Unknown resources 404, invalid query 400, unavailable/corrupt snapshot 503 DATA_NOT_READY; errors include code/traceId and application/problem+json. All API responses no-store. Health explicitly means verified export snapshot, not live upstream health.

DTO contracts are generated from controller signatures in docs/openapi-v1.json. Job contains request/code/source identity, stage chain, counts, quality, optional lineage and separate authority/PIT/approval/research status. Quality contains row quarantine reasons and unknown completeness/price-basis context. Lineage exposes public source URLs/digests, never bodies, local paths or credentials. No write/approval endpoint added.

Intentional security compatibility change: SwingSearch/Data/Backtest, ResearchData, StockRadar, strategy pages and radar job POST/status now require Feature.SwingAnalysis. MarketRadarData and GET /api/v1/market/radar preserve anonymous basic quotes; analyze=true requires membership. Snapshot/industries remain public. Existing personal watchlist/favorite/paper JSON routes return 401/403 JSON instead of HTML login redirects. MVC feature pages and form writes continue redirecting to login. All Paper APIs also require Feature.PaperPortfolio. Existing CSRF, local return URL and ordinary-member versus administrator boundaries remain.

The frontend loads public market quotes without starting an anonymous analysis job; it prompts login. Logged-in analysis remains bounded/progressive. ResearchValidation uses all six new ETL resources. API controllers perform no direct DB/provider access. Schema compatibility tests remain, and explicit authentication behavior tests cover the intentional tightening.
