# 3.2.1 ETL architecture

Application owns IDataProviderAdapter, provider capability/request/response contracts, quality checks, immutable ETL batch, job orchestration and lineage. API controllers expose six read resources through EtlReadAdapter. ResearchValidation fetches these APIs; JavaScript performs presentation only. CLI uses the same Application implementation. ICurrentUser moved from Web to Application without changing namespace or authentication implementation. Api still references Web for existing hosting, Identity/EF and legacy services; this release does not claim complete dependency inversion.

Network acquisition remains the existing registered-source Phase4JAcquisition/EvidenceAcquisitionStore with HTTPS allowlist, DNS public-address validation and pinned socket, disabled redirects/proxies/cookies, 16 MiB cap, 30-second deadline, 10-second connect timeout, one global acquisition lease, 20/provider/hour and three persisted attempts. This release reuses two original SourceArchive objects; no new download, provider purchase, token export, or parallel acquisition engine. TWSE monthly prices/institutional flows reuse OfficialHistoricalSource and OfficialParser. TPEx price-only adapter reuses OfficialParser and leaves exact volume null. FinMind ETL remains MANUAL_ACTION_REQUIRED until explicit authorization and dataset contract exist.

State path: EXTRACTING → EXTRACTED → TRANSFORMING → QUALITY → LOADING → SUCCEEDED. Invalid rows/duplicate keys terminate QUARANTINED without loading any rows in that batch. Errors/cancellation terminate FAILED/CANCELLED. Attempt receipts persist before work; at most three attempts, with per-job filesystem exclusion. Crashed/incomplete jobs cannot be published until a subsequent bounded execution completes; export fails closed. Network concurrency and transform leases have separate scopes.

Identity binds provider/dataset/instrument/date/coverage/source digest/schema/transform code SHA/source URL and synthetic flag. A successful repeated identity returns the replayed original report; changing source or transform creates a distinct version. Raw bytes and metadata, normalized HistoricalFact records, quality and lineage are immutable. Replay recomputes transform, quality and lineage against archived bytes. No secrets or raw body are exposed over HTTP. Body hash identifies bytes, not historical revision authority.

CLI: --etl-run <request.json> <SourceArchive.json> <etl-root> <new-report.json> [--retry]; --etl-replay <etl-root> <job-id>; --etl-export <etl-root> <authority-resolution-root> <new-publication.json>. TransformCodeSha must match the compiled CLI. Use existing --phase4j-acquire for registered historical evidence acquisition. Export calls existing RequireCurrentSources and blocks source invalidation/revision-change receipts. Existing AuthorityResolutionStore baseline also checks that guard. Published HTTP reports are verified release snapshots, not live provider/store monitors; a later offline revocation requires republishing the snapshot.

Normalized batches retain the existing HistoricalFact schema for the controlled dataset/reviewer workflow. They do not auto-write approved datasets or bypass HistoricalDatasetBuilder, ComponentDatasetStore, reviewer evidence or seven PIT gates. Authority/PIT/approval/research remain separately reported. Independent component approvals and TrendSample-v1 remain mandatory. Candidate-v1 weights 25/15/15/20/15/10, 19 features and formula digest are unchanged. No public execute/approve/promote/trade route was added.
