# 本機雙向同步

開啟 https://localhost:7180，使用 Google 登入後，在「Google 行事曆」完成同一帳號授權。選擇日期所屬月份，按「立即雙向同步」。Google Cloud 必須啟用 Calendar API，測試模式下需將該帳號加入測試使用者。

第一次會將該月可支援的 Google 事件匯入工作日誌，並將該月尚未對應的日誌建立為 Google 事件。沒有對應的兩筆既有資料不會以相同標題猜測配對，因此若先前已手動在兩邊建立同一筆，應先整理重複內容。

這是按鈕觸發的雙向同步，不是背景即時同步。任一邊新增、編輯或刪除後，再按同步。既有對應不受月份限制，即使改到其他月份仍會更新。讀取月曆本身不會寫入 Google。

同步標題、內容、日期、時段與刪除。專案、工時、進度、顏色、後續待辦只保留在本機；Google 匯入的新日誌工時預設 0。Google 空說明使用「（Google 行事曆事件）」作為日誌內容。

工作日誌只能表示單日事件，因此跨日、多日全天、重複事件、非一般事件、非本人主辦事件、超出日期或字數限制的事件不會匯入，頁面會回報略過數量。這些 Google 事件仍可在月曆中查看。已同步事件變成不支援格式時會留下問題提示，保留兩邊資料。

兩邊相對上次同步都改動時保留內容，顯示衝突。確認兩邊內容後選擇「保留本機版本」或「保留 Google 版本」；刪除也是一種版本，選擇已刪除的一邊會刪除另一邊。沒有衝突的單邊刪除會在下次同步傳到另一邊。

新增使用先保存於 SQL 的固定 Google event ID，回應中斷後可安全重試。更新與刪除使用 Google ETag/If-Match；本機使用 SQL rowversion 防止同步覆蓋並行編輯。API 失敗不會因為列表缺少事件就判定刪除，已對應的事件逐筆 get 確認。每個使用者的事件對應與衝突處理都檢查擁有者。本機單一程序以使用者鎖序列化同步；未設計多執行個體的分散式排程。

資料庫新增 CalendarSyncLinks 和 WorkLogs.RowVersion；保留既有工作紀錄。執行 EF Migration 後使用。本功能納入 1.2.1 發布，正式網站也可在「Google 行事曆」頁面操作。真實 Google 授權與雙向操作需要帳號擁有者實際驗收；自動測試使用模擬 Google，不會存取個人行事曆。
