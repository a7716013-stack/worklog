## 新增必做：市場分析排行效能優化

2026-11-03 線上 3.1.0 診斷：基本排行回應約 3.37 秒，2,313 筆且無資料警告；相同交易日的 analyze=true 請求等待 55 秒仍無回應，測試端逾時停止，並非已量得伺服器最終完成時間。線上 MarketData__Enabled=true。

程式確認的瓶頸：整批最多 60 檔分析完成才回傳；AnalysisGate 將不同分析請求序列化；SourceCache 在外部下載期間持有全域 semaphore 與 cache.lock；畫面與批次分析缺少整體等待上限及進度回傳。每檔歷史價格、法人、營收請求再放大等待時間。

實作項目：

1. 快取改為依資料鍵合併重複下載，縮短檔案鎖範圍，避免不同鍵下載阻塞已存在的快取讀取；保留跨程序一致性、原子寫入及供應商額度控制。
2. 相同市場、日期、模型版本與資料版本的分析共用工作／結果，加入有界佇列及合理併發限制；不以提高供應商請求量掩蓋問題。
3. 長時間分析改為背景工作，分批回傳進度及已完成資料；定義工作逾時、取消、重啟恢復或失敗狀態、快取有效期與陳舊結果標示。單一瀏覽器離開不得取消其他使用者共用工作。
4. 首次載入先顯示基本排行，再呈現分析進度；提供重試及明確失敗原因，避免無限轉圈。未完成分數不可當成最終推薦排序，缺值不可補零假裝完成。
5. 將市場分析協調、評分與相關資料契約從 Web 抽出到共用服務，網站改用正式 API；過渡 MVC 路由重用同一服務，保持既有呼叫端相容。

## API 設計要求

正式路由沿用 `/api/v1`，實作時核對既有 market radar 契約後定案；需要基本排行讀取、分析工作建立／取得、進度及分批結果查詢能力。既有同步端點不得靜默改成不相容的工作 DTO。

- Request：市場、交易日、模型／公式版本；伺服器驗證市場列舉、可用日期及允許版本。
- Response：jobId、狀態、已完成／總數、部分或完整結果、資料時間、模型／資料版本、警告及可追溯識別；工作建立可用 202 與後續查詢位置。
- 定義重複請求合併鍵、輪詢間隔、工作不存在／過期、排隊滿載、來源額度不足及整體逾時的錯誤碼與 traceId。
- 公開行情不混入個人自選或持股；個人資料維持登入與隔離。建立／取消工作的授權、Cookie CSRF、限流及共享工作取消政策須明定。
- OpenAPI、docs/api-v1.md、契約測試與 UI 同步更新。背景工作的儲存及恢復方式依現有部署能力設計，不預設開啟付費資源。

## 驗收與交付

- 比較冷快取、熱快取、重複請求、多使用者、慢來源、來源失敗及額度耗盡情境，記錄回應時間、外部請求數、鎖等待與佇列等待。
- 可控制測試環境下，工作建立／進度查詢以 2 秒內回應為目標；來源延遲不應阻塞這些操作或無關快取命中。實作時另訂整批工作總期限並驗證到期終止，不承諾外部資料必定在固定秒數到齊。
- 驗證重複分析不重複下載、單檔失敗不讓畫面無限等待、部分結果有明確標記、重啟後工作不永久停在執行中。
- 搬移前後用相同輸入驗證分數、排序與缺值一致；測試 API 契約、相容路由、登入隔離與瀏覽器進度／重試。
- 實作報告列出 API 變動、已移出的運算、剩餘 Web 相依、量測改善及限制。取得發布授權後依同 SHA CI、部署後版本與網站／API 驗證流程上線。
