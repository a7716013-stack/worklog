## 成交、損益與一致性

1. 市價使用伺服器 FinMind 最新可用已完成收盤價，非真實即時成交；台灣時間 14:00 前排除當日。
2. 限價買單 Low ≤ LimitPrice，賣單 High ≥ LimitPrice，成交價均為 LimitPrice。必須滿足 QuoteDate ≥ EligibleFromTradeDate 且晚於 SubmittedTradeDate、LastEvaluatedTradeDate。
3. EligibleFromTradeDate = max(建立台灣日, 建立時行情日)+1 日。即使盤前建立也不使用當日 K 棒，這是刻意保守的日資料規則；實際評估自然等待有行情的交易日，不假造假日行情。
4. 按鈕觸發 pending 檢查，不在 GET 自動成交；每次只看最新 K 棒，不回補中間漏掉的日 K。
5. 手續費 = round(max(20, Gross×0.001425×1), 2)。稅費僅賣出 = round(Gross×TaxRate, 2)，股票 0.003、ETF 0.001，全部可由 Options 調整，非最新法規聲明。
6. AverageCost = (舊 CostBasis + 買進 Gross + Commission) / 新 Quantity。部分賣出平均成本不變，CostBasis 扣除分攤成本；全賣沖销所有剩餘成本。
7. Realized P/L = Gross−Commission−Tax−RemovedCost；同步累加帳戶及部位。Unrealized P/L = Quantity×最新收盤−CostBasis。
8. TotalAssets = Cash + 全部持股市值，TotalProfitLoss = TotalAssets−InitialCash，TotalReturnPercent = TotalProfitLoss/InitialCash×100。缺價時不輸出完整總資產與損益。
9. 下單與成交都驗證數量、價格、現金、持股。賣出若收入不足支付最低手續費，也檢查現金能否補足。不預留 pending 資金／股數，不允許 Cash 或持股變负。
10. EF transaction + SQL sp_getapplock 同步保護 Order/Trade/Position/Cash，包含初始化、取消及重設，跨程序生效。行情在鎖外讀取，鎖內重新確認狀態／餘額。
11. 相同表單 ClientRequestId 重送回傳同一委託；唯一索引、Pending 狀態檢查與成交序號確保不重複成交。交易失敗全數回滾，重試清除追蹤狀態。
12. FinMind 出錯：新委託記錄拒絕；既有 pending 保留，portfolio 保留帳務並標示不完整。共用既有 HttpClient、Bearer、MemoryCache、Gate；每個 request 同股票只讀一次，逐檔讀取限制併發。
13. 全域 Anti-forgery 未放寬，所有變更為 POST。表單專用 ViewModel，客戶端成交價、費用、AccountId、狀態等不列入輸入。
14. Reset 需要勾選及瀏覽器二次確認，POST 再檢查確認值與帳戶 Generation。只刪除虛擬交易紀錄；Generation 輪替讓舊表單／重播重設失效。

## 已知限制

單一共享帳戶，沒有使用者隔離；日資料非 tick，不能保證盤中成交順序；沒有背景撮合、未做部分成交、未處理企業行動／股利／滑價／漲跌停／成交量限制；完整紀錄目前一次載入，未分頁。SQL 帳戶鎖可能在大量併發時等待。測試行情為可重現 fixture，不能當作真實行情驗證。
