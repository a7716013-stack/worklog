# Worklog 1.2.4：推薦績效追蹤

以討論中的「每日前 10＋個人追蹤並存、交易日收盤後保存」為主，實作桌面《績效追蹤.txt》的快照、未來績效、歷史追蹤、統計、模型驗證、研究資訊及虛擬交易來源關聯。本版已由驗證完成的本機版本部署至既有 Azure／Cloudflare 正式網站；GitHub 發布版本為 v1.2.4。

## 使用入口

股票模組導覽新增「推薦績效追蹤」、「績效／模型驗證」、「虛擬單對照」。市場熱門排行的候選卡可加入個人績效追蹤，原「加入自選」仍保存原本個人自選清單，兩者用途不同。

| 路由 | 用途 |
|---|---|
| `/StockAnalysis/RadarTracking` | 每日／個人歷史，日期、市場、產業、分類、分數、代號、20D 結果篩選，20／50／100 筆 SQL 分頁 |
| `/StockAnalysis/RadarSnapshot/{id}` | 保存當下原因、六项分數、風險、均量、法人及事件；兩種推薦基準後續績效 |
| `/StockAnalysis/RadarPerformance` | 分類與產業統計、六個細分分桶、六因子高低分與外資連買對照 |
| `/StockAnalysis/RadarModelValidation` | 導向績效頁模型驗證區，沿用查詢條件 |
| `/StockAnalysis/RadarPaperComparison` | 個人來源關聯委託及既有已實現損益對照 |

所有個人操作要求登入並驗證防偽權杖。每日推薦共享，只有個人手動保存的快照不會出現在公共每日清單。停止個人追蹤停止其績效更新，快照及既有結果保留；恢復追蹤沿用最初加入時間。

## 保存與排程

- 台灣時間 13:30～22:00，每 15 分鐘檢查；啟動後 30 秒先檢查一次，之後對齊整刻。
- 用上市及上櫃的當日官方報價确认確有當日交易資料。休市／來源日期仍舊時，不保存批次、不執行排程績效更新；不以「非週末」取代交易日確認。
- 必須有當日候選與至少一檔可用歷史／當日法人資訊；全體來源未就緒則稍後重試，避免在 13:30 保存整批空評分。
- 先取完整分數 ≥70，由分數高到低；再取不完整評分，依已知分數／可評配分排序；最後以完整 <70 分補充。最多 10 檔，不足則保存實際數量。
- 每日批次與日期／代號都有唯一索引，SQL 應用程式鎖及交易處理同時啟動／手動重試。若先前已手動保存同日同股，沿用原快照，不用新評分覆寫。
- 快照保留完整 V1 JSON、研究 JSON、來源更新時間、實際建立時間及 `ScoreVersion=V1-1.2.3`（表示原公式沿用，網站版號為 1.2.4）。DbContext 拒絕快照更新與刪除。
- 背景排程需網站持續運行；電腦關機、程序停止或主機休眠時不能作業。重啟只檢查當日，不偽造錯過日期的歷史推薦。部署到正式主機時需另確認持續執行設定。
- `RadarTracking:SchedulerEnabled=false` 可停用排程。頁面 GET 不建立快照、不更新绩效；手動按钮為 POST。

## 績效定義

| 基準 | 進場參考 | 第 N 日 |
|---|---|---|
| 推薦日收盤（理論） | 快照 ClosePrice | 推薦交易日之後第 N 個有效日行情收盤 |
| 發布後次交易日開盤 | 實際建立日期之後首個有效日行情 Open | 進場日計第 1 日 |
| 個人加入後次日開盤 | 最初 JoinedAt 台灣日期之後首個有效日行情 Open | 個人進場日計第 1 日 |

`Return = (期末 Close / 參考價格 - 1) × 100`。MFE 為期間 High 相對參考價格的最大正向幅度（下限 0）；MAE 為期間 Low 的最小負向幅度（上限 0）。全部價格與報酬採 decimal；日期以來源實際有效行情計數，空值／零價格及不合理 OHLC 不計入。

18:00 後更新至當日；較早手動更新只算至前一日，避免將未完整日行情算成一天。每次最多 200 筆未成熟推薦與 200 筆個人追蹤，按最久未更新優先，同股合併請求；同筆至少隔一小時重查，來源按股與日期範圍快取。单股來源失敗不停止其餘標的。

未滿 N 日時保留 null；無效／停牌行情狀態會提示。相鄰價格跳動超過 25% 時，受影響的期間暫不計算並提示待確認企業行動；較早已成熟期間不受後來跳動影響。此防護不是完整除權息／分割調整，也不能辨識所有企業行動。已保存成熟期結果不因後續來源空回應或修訂而重寫，來源部分回傳時亦保留既有明細。

沒有配息再投資、滑價及交易成本；收盤基準為理論觀察，尤其事後手動保存的舊交易日不能當成當時可交易的訊號。發布／加入後開盤基準用來分開觀察此差異。

## 統計與模型驗證

- 勝率分母只含該期間非空報酬；平盤計分母、非勝。負報酬與未成熟分開篩選。
- 類別、70–84／85–100，以及細桶 70–74、75–79、80–84、85–89、90–94、95–100 分開；無樣本不填入假數據。不完整與低分補充另列。
- 各期間勝率／均值、5D／20D 中位數、收盤基準 20D 平均 MFE／MAE、產業平均完整分數；使用者切換次日開盤基準時，表格不混用收盤 MFE／MAE（次日開盤的個別 MFE／MAE 在快照明細可看）。
- 六因子高低分以各配分一半分界，缺值排除；按推薦類別分開。外資連買至少 3 日與其餘／缺值分開比較。
- Pearson 分数對 5D／20D 報酬相關係數；樣本不足 2 或變數無變異時 null。每個期間顯示成熟筆數，低於 30 提示樣本不足，不宣稱模型有效或調整權重。
- 列表在 SQL 篩選、排序、Skip/Take；統計 SQL 聚合，只有中位數／相關計算載入必要數值投影，不載入整份快照。查詢範圍最多 10 年。
- 「我的追蹤」統計篩選个人的推薦集合；統計基準仍按所選推薦基準，個人加入日績效在追蹤頁獨立顯示。

## 研究來源與事件

產業取 FinMind TaiwanStockInfo，ETF 明確標示 ETF，缺值為未知，不從名稱猜產業。外資／投信連買連賣沿用 SwingCalculator，不修改 V1 籌碼分數；現有 SwingFlow 未含可靠自營商欄位，因此不虛構自營商資訊。

保留原 TWSE／TPEx 重大公告，補充 TWSE 注意、處置 OpenAPI；事件可分類月營收、法說、股利、增資、減資、重大契約、訴訟、董事會及其他公告，分類不等於利多／利空。來源未提供結構化方向時一律 Unknown，UI 顯示「影響待確認」。補充事件不送回 V1 計分器。

官方來源未提供事件 ID 時，以來源／代號／公告時間／標題的 SHA-256 去重。只允許 http／https 來源連結，文字透過 Razor／textContent 編碼。僅有公告日期的補充來源保守設為當日 23:59:59，快照排除尚未到該時間的事件；其含义與限制顯示於摘要，不回填既有快照。

來源是當時官方 API 可得公告集合，不承諾涵蓋所有歷史公告。補充注意／處置目前為上市來源，上櫃仍使用重大公告；來源失敗會記錄警示，沒有事件不代表沒有消息。

來源文件：[TWSE OpenAPI](https://openapi.twse.com.tw/)、[FinMind 台股技術面資料](https://finmind.github.io/tutor/TaiwanMarket/Technical/)。

## 虛擬單關聯

由歷史推薦／快照頁建立虛擬單，帶入股票代號與 RecommendationId，使用者自行選擇數量、買賣及限價後送出。伺服器先驗證來源可存取且股票一致，然後沿用 PlacePaperOrder 和原 PaperTradingService，成交後建立獨立關聯；重送同 ClientRequestId 不重複成交。若成交成功但關聯失敗，顯示「已建立，來源未成功」而不提示再次下單。

比較頁只讀該帳號既有 PaperTrade 的已實現損益與含成本金額；只有來源關聯的賣出成交才有已實現報酬，不把關聯買單的後續未關聯賣單擅自歸因。顯示最近 500 筆來源關聯中的委託／成交／已重設數。原市場排行的直接虛擬單連結仍為一般委託；欲保存推薦來源，從「推薦績效追蹤」或快照頁進入。

固定 20D 無成本報酬與實際模擬成交持有期間及含費報酬分開標示，百分點差不能單獨解釋成择時能力。重設帳戶令 PaperOrderId 外鍵設 null，保留原始訂單 ID 與推薦歷史。沒有自動下單或背景成交操作。

## 資料庫與回復

Migration `20261006205209_AddMarketRadarTracking` 新增：

1. MarketRadarRecommendations：不可改寫快照，唯一交易日＋代號。
2. MarketRadarCaptureBatches：唯一交易日的每日保存批次。

未更動任何既有交易資料表欄位。正式上線前需備份正式資料庫、先套用 migration，再部署程式。本機已執行 COPY_ONLY CHECKSUM 備份及 RESTORE VERIFYONLY，migration 後逐一比對既有資料表筆數不變。備份位置及筆數證據記錄於 `artifacts/local-migration124.json`，不提交資料庫備份或個人資料。
